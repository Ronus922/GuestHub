# SPEC — חלון הזמנה V2, חילוץ מהרפרנס

> מקור: `design-ref/booking-window-v2.html` (committed בענף זה), רונדר בדפדפן אמיתי
> (Chrome headless דרך Playwright, viewport ‏1600×1000 + ‏390×844) ב-2026-07-26.
> ה-bundle הוא React self-extracting — הניתוח נעשה על ה-DOM החי אחרי unpack, לא על ה-template.
> צילומים: `docs/booking-window/shots/step{1-4}.png`, `mobile-step1.png`.
> **ה-SPEC הזה הוא מקור האמת ל-UI. חוקי החישוב — לפי הזמנת העבודה (BOOKING WINDOW V2).**

## מבנה כללי

- `SidePanel` צד-ימין (RTL), כותרת "הקמת הזמנה חדשה", תת-כותרת "אורח · שהות · תמחור · אישור".
- פס התקדמות 4 עיגולים: **1 פרטי אורח → 2 שהות וחדרים → 3 תמחור ותשלום → 4 סיכום ואישור**; שלב שהושלם מקבל ✓; מותר לחזור אחורה ("הקודם").
- Sidebar קבוע "סיכום הזמנה": שם אורח + מקור, כרטיס per-חדר (חדר · סוג, תאריכים, אורחים, ₪ לחדר), "לילות סה״כ", "אורחים", **"סה״כ" מודגש**, תג "סטטוס תשלום".
- Footer: "הבא" (primary) / "הקודם" / "שלב N מתוך 4" / "ביטול"; בשלב 4 — "✓ צור הזמנה".
- Header כחול עם פעולות: mail · whatsapp · PDF · print · עין · X.

**מיפוי למערכת:** ‎1:1 על האשף הקיים ב-`BookingPanel.tsx` (‏`STEPS` :57 — אותם 4 שלבים בדיוק, אותו סדר). מרחיבים את הקיים; אין בנייה מחדש.

## שלב 3 — תמחור ותשלום (המסך המרכזי)

### כרטיס "תמחור ותשלום"

- **בורר מטבע** בראש הכרטיס: ‏₪ ILS / ‏$ USD / ‏€ EUR (במערכת: מ-`settings.enabled_currencies`).
- **בלוק per-חדר** (חדר · סוג, לילות, תאריכים):
  - Segmented ‏3 מצבי מחיר: **"מחיר מקורי"** (ברירת מחדל) / **"מחיר ידני ללילה"** / **"סה״כ מחיר"**.
  - תוכנית תעריף: select (ללא החזר/תעריף חודשי/ביטול גמיש במוק; במערכת — `ratePlans`).
  - "מחיר ללילה (₪)" + "סה״כ לחדר (₪)" — שני inputs; המצב קובע מי מהם editable (ב"מחיר מקורי" שניהם readonly ומציגים את המנוע).
  - ⇒ **מצב מחיר הוא פר-חדר, כולל "סה״כ מחיר" — מוכרע: `reservation_rooms.price_mode`, אין מצב ברמת הזמנה.**
- **סקשן "הנחה"**: segmented יחידה + שדה ערך אחד שתוויתו מתחלפת ("הנחה ללילה (₪)" וכו') + hint "בחרו יחידת הנחה והזינו ערך — החישוב מתעדכן מיד." במוק 3 יחידות: ‏₪ ללילה / ‏% ללילה / ‏% להזמנה. **הזמנת העבודה גוברת על המוק בחוקי חישוב: 4 יחידות** (+ ‏₪ להזמנה) **+ מצב "מחיר מלא"** = ללא הנחה (ערך 0 ⇔ none). ראה סטייה ס-2.
- **שורות סיכום**: "מחיר מלא ₪350" / "הנחה −₪0" / **טוגל "מע״מ (18%) — כלול במחיר" ₪53** (ON כברירת מחדל; כיבוי ⇒ פטור ממע״מ) / **"סה״כ לתשלום" מודגש**.

### סקשן "תשלום" (בהמשך שלב 3)

- כותרת עם **"יתרה ₪350"** + progress "שולם ₪0 מתוך ₪350 · 0%".
- chips סטטוס תשלום: לא שולם/שולם חלקית/שולם מלא/ממתין לאישור — ראה סטייה ס-3.
- **אמצעי תשלום**: select — כרטיס אשראי/מזומן/העברה בנקאית/ביט/PayPal (במערכת: lookups `payment_methods`).
- "סכום ששולם (₪)".
- **בחירת "כרטיס אשראי" פותחת "פרטי כרטיס אשראי" ישירות להקלדה** (תלונה 7 — מאושר במוק): שם בעל הכרטיס*, מספר כרטיס*, תוקף* ‏MM/YY, **CVV*** (input type=password, "3–4 ספרות"), תעודת זהות (לא חובה). **אין שדה הערות חיוב** — תואם D109.
- כפתורים: "שמור פרטי כרטיס", "סלוק עכשיו · ₪350" (+ "טרם בוצע חיוב בכרטיס זה") — ראה סטייה ס-4.

## שלב 4 — סיכום ואישור

- אורח + מקור (readonly), שורת חדר (תאריכים, לילות, ₪/לילה, אורחים, סה״כ).
- פירוט: מחיר מלא / **"הנחה · <תווית היחידה הפעילה>" −₪X** / מע״מ (18%) — כלול במחיר / **סה״כ לתשלום**.
- **סטריפ יתרה — 3 קופסאות**: "שולם עד כה ₪0 (כרטיס אשראי · 0%)" / **"יתרה לתשלום ₪350 · טרם שולם"** (מודגש אדום) / "סטטוס תשלום · לא שולם (1 לילות · 2 אורחים)". ⇒ **יתרה מוצגת ביצירה** (דרישה 4; במערכת: `formatBalance` + "זיכוי ללקוח" ליתרה שלילית).
- **"הערות להזמנה"** textarea ("בקשות מיוחדות, שעת הגעה, הערות פנימיות…").
- **"מדיניות ביטול"** — כרטיס **מתחת** להערות (⇒ הסדר המבוקש בתלונה 11 מאושר גם ליצירה): מדרגות + "ביטול לאחר המועד יחויב בלילה הראשון."
- Footer: "✓ צור הזמנה".

## לוגיקה מחייבת (מהמוק + הזמנת העבודה)

1. בחירת אמצעי תשלום "כרטיס אשראי" ⇒ שדות הכרטיס נפתחים להקלדה מיידית (יצירה ועריכה). בחירה אחרת אינה מוחקת טיוטה בלי התרעה.
2. מצבי מחיר per-חדר; "מחיר מקורי" = מנוע (כולל LOS אוטומטי); ידני-ללילה/סה״כ דורשים `reservations.price_override`; "סה״כ מחיר" מדויק לאגורה, פיזור ללילות תצוגה בלבד.
3. הנחה ברמת הזמנה בלבד (אין הנחה פר-חדר במוק) — יחידה + ערך; "החישוב מתעדכן מיד".
4. מע״מ כלול ברירת מחדל; הטוגל פר-הזמנה; שיעור מההגדרות; שורת המע״מ מציגה את הסכום הכלול.
5. יתרה = סה״כ − שולם, מוצגת בשלב 3 (header התשלום), בשלב 4 (סטריפ) וב-sidebar (תג סטטוס).
6. Sidebar חי — מתעדכן עם כל שינוי (אורח, חדרים, סה״כ, סטטוס).

## סטיות SPEC ↔ מערכת — הכרעות

- **ס-1 · בסיס אירוח (board basis):** קיים במוק, אין לו שום מודל נתונים במערכת (rate plans אינם board-aware) והזמנת העבודה אינה מזכירה אותו. **הכרעה: מחוץ להיקף V2** — יירשם ב-DECISIONS; יתווסף רק עם מודל תעריפים תואם. ה-UI לא ירונדר select מנותק.
- **ס-2 · יחידות הנחה:** המוק מציג 3 (חסר ‏₪ להזמנה — היחידה היחידה שקיימת היום!). הזמנת העבודה דורשת 5 מצבים. **הכרעה: UI בסגנון המוק (segmented) עם 4 יחידות; "מחיר מלא" = ערך 0/none** (שורת הסיכום תמיד מציגה "מחיר מלא"). **סגור — הקוד תואם (D155).** ‏`DISCOUNT_UNITS` ב-[PricingControls.tsx](../../src/components/reservations/PricingControls.tsx) מציע את ארבע היחידות, בסדר הזה (סדר המערך = סדר ה-DOM = סדר ה-RTL מימין לשמאל): ‏**₪ ללילה · ₪ להזמנה · % להזמנה · % ללילה**. ‏‎`amount_total` הוסר מן הלשוניות ב-#180 והוחזר כיחידה מן המניין; החברוּת והסדר מוקפאים ע"י `check:discount-units`.
- **ס-3 · chips סטטוס תשלום:** במוק בחירה ידנית; במערכת המצב נגזר מסכומים (`paymentState`). **הכרעה: נשאר נגזר** — chips מוצגים כמצב, לא כקלט (שינוי מודל התשלום מחוץ להיקף).
- **ס-4 · "סלוק עכשיו":** נשאר במצב הקיים (disabled, "לא מוגדר ספק סליקה פעיל") עד שיוגדר PSP.
- **ס-5 · פעולות header (mail/whatsapp/print/PDF/עין):** מחוץ להיקף V2 (לא בהזמנת העבודה); קיימות חלקית במערכת במסכים אחרים.
- **ס-6 · שפה/מדינה/חברה בשלב 1:** ירונדרו אם השדות קיימים במודל האורח; אחרת יידחו (לא חוסם F).
- **ס-7 · מדיניות ביטול ביצירה:** המוק מציג את הכרטיס גם ביצירה (שלב 4) — יתווסף (תצוגת snapshot התבנית הפעילה), הסדר: הערות מעל מדיניות.
