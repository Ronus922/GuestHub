## F.3 — `fee07a5b`: שער, לא מקור מחיר

**מה היא.** `code = No_Refuneble` · `name = "ללא החזר"` · **ברמת הדייר**
(`sellable_unit_id IS NULL`) · `plan_kind = 'base'` · `parent_plan_id = NULL` ·
`is_base = **false**` · `adjustment_value = **NULL**` · `default_min_stay = 1` ·
`default_max_stay = **NULL**` · `is_refundable = **false**`.

**לאן היא ממופה.** ל-**15 מתוך 15** המיפויים ב-`channel_beds24_room_mappings`.
כל חדר ממופה מצביע עליה, ורק עליה.

**האם היא משתתפת בחישוב המחיר — לא. הנה המסלול המלא:**

```
beds24-ari-projection.ts
  getRoomPlanRates(db, tenant, roomIds, …)      ← המחיר מגיע מכאן
      └─ pricing_plan_rates של תוכנית ה-is_base של היחידה  (eea48ca8 → 750)
  overlayRows  ← FROM guesthub.pricing_plan_unit_rates
      └─ WHERE pricing_plan_id = ANY(chain of fee07a5b)
  mergeRestrictionRows(dates, baseByDate, overlay, plan)
```

**נמדד:** `fee07a5b` מחזיקה **0 שורות תעריף**, ו-`pricing_plan_unit_rates` —
הטבלה שהפרויקציה קוראת ל-overlay — **ריקה לחלוטין ברמת הדייר (0 שורות)**.
ה-overlay תמיד ריק, ולכן `merge` מחזיר את שורת הבסיס כמות שהיא.

**מה כן עושה `fee07a5b`, ולכן היא לא בלתי-מזיקה:**

1. **שער פרסום.** `!assignment || !assignment.isActive → RATE_PLAN_NOT_ASSIGNED` —
   זה בדיוק מה שהחזיק את 1318 סגור עד 15:50.
2. **ברירות מחדל של הגבלות.** `minStayArrival = maxNullable(m.min_stay_arrival, plan.defaultMinStay)`
   ו-`maxStay = minNullable(m.max_stay, plan.defaultMaxStay)`. כאן
   `default_min_stay = 1` (לא מזיק) ו-`default_max_stay = NULL` — **ולכן היא
   אינה מהדקת את ה-maxStay שנוקה ב-D99. נבדק במפורש.**
3. **חלונות תוקף ו-`allowed_checkin_days`** של התוכנית חלים לכל תאריך.
4. **שורש שרשרת** לשלוש תוכניות-הבת.
